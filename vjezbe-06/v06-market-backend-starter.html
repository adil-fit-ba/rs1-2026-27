Market Backend: od MojaApp do startera

Isti slojevi kao u MojaApp V05, uz prijavu, jedinstven oblik greške i gotove module.

Market Backend je backend početnog projekta za projektni zadatak. Za vježbe je pripremljen na .NET 8, s bazom podataka na LocalDB-u. Slajdovi prikazuju stvarni kod iz ZIP-a za V06, a svi odgovori API-ja snimljeni su na novoj bazi podataka.

Na ovom času: pokretanje, put zahtjeva, JWT, CRUD nad kategorijama i vježba u paru. Na narednom času: narudžba sa stavkama (master–child).

Pokretanje

Prvi zahtjev: javna lista kategorija

API pri prvom pokretanju kreira bazu podataka Market_V06, primjenjuje migracije i upisuje demonstracijske podatke.

  1. ZIP raspakovati u kratku putanju, npr. C:\RS1\V06, a ne u Downloads ili OneDrive. Rješenje je Market.Backend\Market.Backend.sln.
  2. U folderu Market.Backend izvršiti komande iz bloka ispod. Komanda dev-certs otvara dijalog za potvrdu certifikata.
  3. U Visual Studiju odabrati startup projekat Market.API i profil https.
  4. Otvoriti https://localhost:7100/swagger i izvršiti GET /ProductCategories.
PowerShell · folder Market.Backend
dotnet --version
dotnet dev-certs https --trust
dotnet run --project Market.API --launch-profile https

Očekivani rezultat komande dotnet --version je 8.0.x. Ako SQL Server nije na instanci (localdb)\MSSQLLocalDB, connection string se zadaje varijablom okruženja ConnectionStrings__Main.

Vježba u paru

Novo polje kroz sve slojeve: opis kategorije

Kategoriji se dodaje neobavezan opis Description dužine do 500 znakova. Poslije svakog koraka uraditi build.

#Projekat i fajlŠta
PowerShell · folder Market.Backend
dotnet tool restore
dotnet ef migrations add CategoryDescription --project Market.Infrastructure --startup-project Market.API --output-dir Migrations
Package Manager Console · Default project: Market.Infrastructure
Add-Migration CategoryDescription -Project Market.Infrastructure -StartupProject Market.API -OutputDir Migrations

Prije pokretanja pregledati migraciju: treba dodati jednu kolonu Description, nvarchar(500), koja dozvoljava NULL. API je automatski primjenjuje pri pokretanju.

Pitanje za par

Zašto PUT bez polja description briše opis? PUT šalje cijelo stanje kategorije: polje koje nije poslano dobija vrijednost null, a handler je upisuje.

Dodatno, za parove koji završe ranije

PUT /ProductCategories/{id}/name, po uzoru na …/disable i …/enable: u tijelu je samo naziv, a ID je iz rute. Validator provjerava naziv na isti način kao UpdateProductCategoryCommandValidator, a handler provjerava postoji li druga kategorija s istim nazivom (409). Naredni GET pokazuje novi naziv, a isEnabled i description ostaju isti.

Provjereno na kopiji ZIP-a za V06: build s 0 upozorenja, testovi 67/67, svi zahtjevi iz tabele daju očekivane statuse.
